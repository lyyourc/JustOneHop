# zing

简体中文 · [English](README.en.md)

一个让日常浏览器操作更顺手的 Chrome 命令面板。

个人本地加载版，无账号、后端或遥测。

## 功能

### Command Palette

在一个入口查找标签页、书签、浏览历史和浏览器命令。命中词仅加粗提示，相关命令优先，常选结果按使用习惯前移。点击结果或按 Enter 执行，通过「操作」菜单管理选中的标签页。

关闭、固定、静音等整理操作完成后，zing 保持打开，保留搜索和输入位置；删除结果后选中相邻项，可连续整理。切换标签页、打开页面等导航操作完成后关闭面板。若关闭了承载 zing 的当前页，会在同一浏览器窗口的独立面板中接续搜索（保留系统标题栏），先重新选择结果再继续操作；关闭整个来源窗口或最后一页时不接续，也不会跨窗口追随。

### 浏览历史搜索

输入关键词时同时搜索 Chrome 最近一周的历史（不限定从 zing 打开的页面），最多返回 100 个历史匹配；等待最多 100ms 后与其他来源一次性呈现，迟到结果不插入。普通关键词的第 5 条提供「搜索全部历史」（不足 4 条结果时放末尾）；输入 `history / 历史 / 搜索历史` 时该入口置顶，进入空搜索框，点击或 Enter 在面板内搜索全部时间；加载时仍可编辑关键词或返回。超时、无匹配与读取失败分别提示。历史页面在来源窗口新标签页打开，与匹配标签页／书签相同 URL 的历史候选去重。安装时申请 `history` 权限，只读 HTTP(S) 历史，不缓存历史库或记录历史点击权重，无痕窗口不读取普通历史。

搜索结果共用图标、标题与说明、右侧元信息布局。历史显示最近访问时间（刚刚、几分钟前、今天／昨天时分或日期），悬停可查看完整本地时间；窄屏仍保留时间。

### Chrome 内置页面

搜索 `extension`、`password` 或相应中文关键词，快速打开扩展管理、密码管理器、下载内容、历史记录、书签管理器、Chrome 设置和扩展快捷键。当前窗口已有相同目标地址时切换过去，否则新建标签页；保留当前网页及原生页面中的其他子页。输入「Chrome 内置页面 / Chrome Pages」可查找整组入口，空搜索时不显示。`settings / 设置` 仍打开 zing 设置。这些入口只负责跳转，不读取密码、历史或下载数据，不增加权限。

### Tab Switcher

按最近使用顺序切换当前窗口的标签页，也可输入标题或网址筛选。按住快捷键连续选择，松开确认，快速回到上一个标签页。

### 脚本收藏

搜索「脚本 / scripts」管理本机保存的脚本：左侧列表选择脚本，右侧即时显示只读代码预览、名称和内容类型 JavaScript。单击仅选择预览，悬停不改变选择；方向键或 Ctrl+N/P 同样切换预览，Enter 或底栏「复制代码」复制选中脚本。编辑从右键或「操作」菜单进入，内置项提供「查看配置说明」。底栏「新建脚本」（窄屏为加号）或 Cmd+Shift+N（Windows/Linux 为 Ctrl+Shift+N）创建，名称与代码表单用 Cmd/Ctrl+Enter 保存，删除需确认。宽度不超过 520px 时列表在上、预览在下，两者独立滚动。搜索「运行脚本 / run script」仍打开全宽选择列表，点击或 Enter 在当前网页运行一次。脚本仅显式运行，不自动展开文本或随网页加载执行；结果只留在当前面板。

### 页面存储

搜索 `local storage`、`session storage` 或 `cookie` 查看当前网站存储。与脚本收藏一致，左侧选择 key，右侧上方直接展示只读 value，下方显示 key、内容类型与 Cookie 属性；单击只选择，Enter 或底栏「复制值」复制原始字符串。JSON 自动格式化预览，Cookie 保留域名、路径等属性；窄屏上下排列并独立滚动。存储只读，Cookie 按网站授权，内容仅保留在当前面板。

### Auto Tuck

把 7 天未使用的标签页自动放进折叠的「已收起」组，让标签栏留给正在做的事。页面保持打开，随时搜索或点击找回一页。默认关闭，也可手动收起、撤销收起。

## 交互原则

**Human first**：人可以用熟悉的快捷键，也可以用鼠标，并随时在两者之间切换。使用 zing 不应以记住快捷键为前提。

- **操作找得到**：常用操作有清楚、可点击的入口，更多操作集中在「操作」菜单；快捷键在对应入口旁提示。
- **同一操作，同一逻辑**：点击与快捷键使用相同的操作、状态和返回路径，切换输入方式不丢失当前上下文。
- **反馈及时，返回自然**：执行、等待、成功和失败都有明确反馈；返回上一层保留搜索、选中项和编辑位置，文本编辑遵循熟悉的习惯。

这些原则是后续设计与验收的标准。

## 安装

需要 Node.js / npm 和 Chrome 127+。

```sh
npm ci
npm run build
```

1. 打开 `chrome://extensions`，开启「开发者模式」。
2. 选择「加载已解压的扩展程序」，加载本项目生成的 **dist/** 目录。
3. 点击工具栏的 zing 图标，或按 **Cmd+Shift+P**（Windows/Linux 为 **Ctrl+Shift+P**）。

`dist/` 不纳入 Git，首次克隆后需要构建。快捷键冲突时，在 `chrome://extensions/shortcuts` 中修改；也可搜索「快捷键」进入设置。

## 开始使用

输入中文或英文关键词即可统一搜索，无需模式前缀。例如页面标题、网站域名、`new tab`、`settings`，也可按日常说法检索（如 `refresh page / 刷新页面`、`reopen last tab / 恢复标签`、`dark mode / 深色`、`打开书签`），或组合标题、域名、标签组与书签目录（如 `github pull`、`notion 路线`、`前端 react`，词序不限）。

无需输入完整命令名称：`clo` 可找到关闭标签页，`clo oth` 找关闭其他，`tab clo ri` 找关闭右侧（「关闭」和 `guan` 同样可用；`cl`、`cloud` 或单独 `tab` 不会误触关闭操作）。静音与固定命令会根据目标标签页当前状态过滤反向别名。搜索排序优先保证相关性，本机使用习惯仅在同一相关性等级内微调。

| 操作 | 鼠标入口 | macOS 快捷键 |
| --- | --- | --- |
| 执行搜索结果 | 点击结果或底栏主操作 | `↑` / `↓` 或 `Ctrl+P` / `Ctrl+N` 选择，`Enter` 执行 |
| 当前候选项的更多操作 | 右键候选项，或点击底栏「操作」 | `Cmd+K` |
| 打开设置 | 底栏设置齿轮 | `Cmd+,` |
| 返回上一层 | 点击底栏返回箭头或搜索框尾部 `esc` | `Esc`（二级页空搜索框也可用 `Backspace`） |
| 关闭主面板 | 搜索框尾部 `esc` | `Esc` |

右键点击工具栏的 zing 图标，可查看当前实际绑定并前往修改快捷键，或在新标签页打开内置「使用帮助」（也可从「设置 → 通用 → 使用帮助」或主搜索 `help / 帮助 / 使用说明` 在面板内打开）。

切换最近标签页时，按住 `Control+J`（或已配置的 `Ctrl+Tab`），用 `N` / `P` 或方向键选择，松开修饰键即可切换；若点击切换器搜索框或按 `Cmd/Ctrl+F` 进入筛选，则暂停松键切换，可松开按键正常输入标题或网址，再按 `Enter` 或点击结果确认。

Windows/Linux 使用 `Ctrl` 代替 `Command`，最近标签页切换默认使用 `Ctrl+,`。更多用法与平台差异见[使用指南](docs/USAGE.md)。

## 使用边界与数据

普通网页显示按页面视口水平居中、偏上的浮层，最大 750×516px，小视口按可用空间缩小。Chrome 内置页的命令面板，以及最近标签切换无法使用网页浮层时，使用独立窗口，按来源内容区与缩放比例估算位置，内容缩放跟随来源页，并在显示界面前通过 Chrome API 返回的窗口与标签页尺寸校准自身原生边框；系统标题栏仍保留。

独立窗口使用 Chrome 返回的来源标签页内容尺寸和浏览器外框尺寸（DIP），按水平对称、底边对齐估算内容区，再结合来源页缩放计算位置和尺寸。来源内容区的屏幕原点无法直接测量，垂直标签栏、停靠 DevTools 和系统边框可能造成偏差，不能保证像素级对齐。

命令面板在普通网页地址栏持有焦点、Web Store 等其他受限场景仍使用工具栏弹窗，其位置由 Chrome 控制。最近标签切换在地址栏等未监听区域快速点按时可能需要 Enter 确认。

偏好、保存的脚本及搜索使用记录只存本机；页面存储值和脚本结果仅保留在当前面板。

收起不会关闭或主动卸载页面。重启浏览器或重新加载扩展后，zing 会根据本机保存的记录恢复管理；无法唯一确认时，搜索「恢复收起组」，在成员详情卡片中核对页面，点击卡片仅选择候选组，再从底栏或操作菜单选择「继续管理这组」明确确认。待确认期间避免重复建组。记录只在本机保存，不记录无痕页面。详见 [收起标签页](docs/USAGE.md#收起标签页)。

其他功能、权限与限制，以及 Ctrl+Tab 手动配置见 [使用指南](docs/USAGE.md)。

## 开发与测试

React、TypeScript、Fuse.js、esbuild。测试使用独立临时浏览器配置和本地页面。

```sh
npm run dev                       # 监听源码并构建
npx playwright install chromium   # 首次浏览器测试前安装
npm run check                     # 类型检查、单元测试、构建、端到端测试
```

日常按[测试指南的分层矩阵](docs/TESTING.md#按影响范围验证)选择类型检查、模块单测和少量相关浏览器用例；纯布局调整不默认运行完整单测。`npm run test:e2e -- --grep '<用例筛选>' --list` 仅选例，不构建或启动浏览器；去掉 `--list` 才构建并执行。每轮保存独立产物、阶段耗时与 `validation.json`。`npm run check` 运行完整套件，当前定位矩阵仍有未解决项。`ZING_CHROMIUM_PATH` 可指定 Chrome for Testing 可执行文件；Vimium 兼容用例仅在提供 `ZING_VIMIUM_PATH` 且确认扩展加载后执行，缺少路径时明确跳过。运行方式与验收边界见[测试指南](docs/TESTING.md)。

构建后打开 zing，搜索 `Zing: Reload`、`reload zing` 或「重新加载扩展」，点击「Zing: 重新加载」或按 Enter 即可加载本机已构建版本；zing 面板会关闭，网页和已保存设置保留，再次唤起即可使用。首次安装此功能仍需在 Chrome 扩展管理页手动重新加载一次；扩展无法启动时也可使用该入口。`public/` 的 manifest 或语言包改变后需重新运行构建。`dist/`、依赖和测试截图不提交到 Git。
