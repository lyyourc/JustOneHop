# 0013 · 扩展图标菜单、实际快捷键与独立帮助页

状态：已采纳。记录日期：2026-10-17。记录本次已确认的产品决策，不作为实现验收证据。

## 背景

常驻的空搜索启动提示占用主搜索空间。用户需要可通过鼠标找到的快捷键修改和帮助入口，也需要在不打开网页面板、不请求网站权限的情况下阅读帮助。

## 决策

移除主搜索的常驻启动提示。通过 `chrome.contextMenus` 仅注册两个 `contexts: ['action']` 项：本地化的「打开 zing：实际快捷键 · 修改快捷键 / Open zing: actual shortcut · Change shortcut」和「使用帮助 / Help」。文案跟随 zing 语言偏好，Chrome 决定菜单外观与分组；不向网页右键菜单添加入口。本次仅新增 `contextMenus` 权限。

快捷键项点击后使用现有 Chrome 页面导航逻辑：在调用窗口复用精确匹配的 `chrome://extensions/shortcuts` 标签页，无匹配则新建，不替换当前网页或跨窗口复用。绑定仍由用户在 Chrome 中修改。

帮助项每次在调用窗口新建扩展自带的 `help.html` 标签页，不复用已有帮助页。独立页复用 `HelpView`、搜索、共享控件及现有主题／语言偏好；内容随构建打包，可离线阅读，无需网站权限。内嵌入口继续从主搜索或设置进入，返回时恢复父页面上下文。

独立帮助的控件明确标为「关闭帮助 / Close Help」，底栏提供显式关闭操作。点击关闭、点击搜索尾部 Esc、按 Esc 或在空搜索框中按 Backspace，均关闭帮助标签页；有文字时 Backspace 仍删除文字。两种承载共用返回路由及输入法、修饰键和长按保护，不另建一套帮助导航。

后台通过 `chrome.commands.getAll()` 获取实际绑定，在 service worker 初始化、安装／启动、标签页激活、窗口聚焦、快捷键页更新、面板快照读取及语言变更时刷新菜单。帮助的打开与搜索章节也显示实际绑定及展开的按键名称；未绑定时明确说明。此功能不增加轮询或存储。

## 取舍与边界

Chrome 不提供 `contextMenus.onShown` 或命令绑定变更事件。用户在同一标签页改键后立即右键时，菜单可能仍显示旧绑定。切换标签页或打开 zing，再重新打开菜单可更新显示。事件刷新不能承诺每次右键前都同步，也不能控制 Chrome 对菜单的分组方式。

新建帮助标签页会增加一个标签，但使其关闭操作有明确目标，不会接管用户已打开的帮助页。独立帮助不改变 Command Palette 或 Tab Switcher 的承载及定位策略，也不恢复暂停中的屏幕定位工作。

## 未采用的方案

- 保留常驻启动提示：持续占用主搜索空间，工具栏菜单和帮助章节已有对应入口。
- 向网页右键菜单添加帮助：扩大入口范围，不符合仅扩展图标菜单的边界。
- 用定时轮询追踪快捷键：增加后台工作，仍不能替代 Chrome 缺失的变更事件。
- 单独维护外部帮助网站或第二套帮助组件：增加网络依赖或内容与交互分歧。
- 复用已有帮助标签页：可能切离用户当前阅读状态，关闭语义也不再对应本次新建页面。
