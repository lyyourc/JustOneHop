# 0007 · 实时快照、局部复用与延迟加载提示

状态：已采纳；成功后的面板去向于 2026-10-17 由 [ADR 0012](0012-continuous-tab-management.md) 更新为按操作意图区分。记录日期：2026-10-15，基于现有实现与历史验收补录；不代表这些决策在同一天首次作出。

## 背景

用户希望打开快、尽量不出现 Loading。已有测试显示普通重复打开通常在百毫秒附近；尚无证据表明全量快照读取是主要瓶颈，新增会话快照缓存会带来过期目标与刷新选择漂移的复杂度。

## 决策

保留标签状态和快捷键实时读取，不新增会话快照缓存。仅复用书签树及并发读取，书签变化后失效；复用同一候选数组的搜索索引，不缓存排序结果。

首屏 Loading 延迟 150ms，数据或错误返回时取消，重试重新计时。已显示结果的后台刷新不清空列表。浏览器操作完成即通知面板关闭，后台仍等待使用记录写完。

## 取舍与影响

快速读取不再闪烁 Loading，但此变化不减少实际读取耗时。首次打开仍等待真实数据；若后续测量出现显著瓶颈，再重新评估快照缓存。局部缓存需要失效处理，操作完成与学习持久化则必须分别处理失败。

## 未采用的方案

本轮明确暂不采用“先显示会话缓存再后台更新”，也不通过延迟展示真实结果来保证 spinner 最短可见时间。
