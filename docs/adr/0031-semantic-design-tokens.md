# ADR 0031：以语义 token 维护跨视图视觉系统

- 状态：已采纳；验证范围见验收矩阵
- 日期：2026-10-23
- 关系：延续 Chrome Native 产品边界与 ADR 0030 设置框架；视觉契约归交互架构 §5.1

## 背景

设置侧栏、独立任务页和存储详情需要不同的信息组织，但同类按钮、字段与说明不应因所在页面而改变外观。仅逐页统一边距，无法避免字号、圆角、焦点和禁用状态继续分叉。

## 决策

参考 [Adobe Spectrum 的 design tokens 分层](https://spectrum.adobe.com/page/design-tokens/)，采用基础尺度、语义角色、组件尺寸三层。借用组织方法，保留本产品的系统字体、Chrome 灰阶、单色图标槽和柔和蓝色选中态，不引入外部组件库或远程字体。

- 基础尺度提供间距、字号、字重、圆角和动效时长。
- 语义角色描述正文、辅助信息、字段标签、内容留白、卡片、控件状态、焦点和表面颜色。
- 组件尺寸保留搜索栏、结果行、底栏等已有紧凑契约，避免将所有内容强制套入同一种密度。
- 同类正文动作和表单字段使用共享样式，不以所在页面或承载方式改变外观。代码内容采用同一等宽字体规格；只读预览与表单仍可使用不同容器。
- 页面标题、字段标签与数据条目名称按角色区分；存储键名不是大型展示标题。统一并不意味着所有标题或圆角都相同。

## 取舍与维护

共享 CSS 是 token 的可执行来源，两种承载均从它取得同一视觉规则。保留现有已具语义的颜色名称，减少纯命名迁移。新增视觉值先匹配已有角色；确有不同职责时再添加组件 token，不能按页面名称创建一套同义尺度。

正文、辅助说明、紧凑元信息分别使用 13px、12px、11px；键帽和搜索／结果／底栏保留组件级字号。字体、字重、行高、视觉间距、圆角、边框、焦点、表面、阴影和状态使用共享 token。窄屏通过换行、截断和布局适配保留同角色文字尺度，不另设更小字号。宿主背景与应用内部使用同一主题颜色来源。

token 不替代几何约束：视口定位、百分比、断点、可滚动区域上限、开关轨道内部构造以及屏幕阅读器隐藏区域属于布局或绘制参数；用户 Emoji 的字号随图标槽尺寸变化，不属于正文排版。原生标签组颜色使用独立语义色。不得为每个遗留数值创建一个同名页面 token 来规避角色归并。

不用 token 替代布局判断：长说明仍需分组、主要操作仍应靠近对应字段。静态检查约束共享样式的视觉字面量和 token 引用；验收比较同角色控件在不同视图中的实际渲染，并检查深浅色、键盘焦点与窄屏；仅声明变量或静态检查通过不构成视觉一致性的证据。
