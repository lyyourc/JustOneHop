# 0008 · 原生标签组收起与持久恢复

状态：已采纳。记录日期：2026-10-15。依据本轮已确认的产品原型、接口、本机存储及权限方案。

## 背景

长期开着的旧标签页挤占标签栏，但要求用户逐一判断、关闭又增加整理负担。用户希望保留少量正在使用的页面，并随时找回暂时不用的内容。自动关闭会失去页面内存中的状态，而“收起”应当如实表示页面仍然打开。

## 决策

使用 Chrome 原生标签组，在每个普通窗口末尾创建一个折叠的「收起来」（Tuck Away）组。默认组名不附加成员数量，避免名称中的数量过期；成员增减不改变名称。已确认归属的旧自动名称更新为当前名称，用户自定义名称保留。默认不启用自动收起；用户开启后，以 7 天未使用作为初始期限，在空闲时检查。跳过当前、固定、已有分组、播放声音、加载、多选、分屏和无痕页面。收起不调用关闭、重新加载或 discard 操作。

找回沿用既有搜索和切换动作，只移出确认选中的一页。Tab Switcher 在选择期间不激活目标，因此不会提前移出组。撤销仅处理当前窗口最近一批、仍在原归属组内的标签页；不恢复已关闭页或回滚窗口的历史排序。找回和撤销重新开始闲置计时。关闭开关停止自动检查并移出当前仍确认归属的标签页。

在已有偏好中增加默认关闭的 `autoTuck`，快照增加收起与撤销状态，已有执行接口增加手动收起和撤销操作。展示与操作接入既有搜索、底栏和操作菜单，鼠标与键盘使用同一条执行路径，不增加快捷键。

## 本机状态与归属

`chrome.storage.session` 保存本次浏览器会话的组 ID、窗口 ID、成员、预期标题和最近可撤销批次。Chrome 后台工作进程休眠不等于浏览器会话结束；唤醒后可继续管理已确认的组。每次处理前检查归属，用户改名、改颜色或加入新成员后放弃管理。

持久计时只记录当前开放页面的网址和最近使用时间，用于浏览器重启后的闲置判断；关闭自动功能会清空计时。相同网址取较新的时间；缺少可信记录时从当前时间开始。

另用 `zingTabTuckRecovery`（version 1）保存随机记录键、预期组名、完整成员网址多重集、窗口其他 HTTP(S) 页面网址多重集。数字组 ID 和窗口 ID 只用于当前会话，不作为跨会话身份证明。启动、后续标签组事件以及存在待恢复记录时打开面板，都会重新核对记录：名称、灰色、成员与窗口上下文完整且一对一匹配时恢复管理。窗口暂未恢复时保留记录，避免一次启动检查永久丢失归属。该匹配是证据推断，Chrome 未提供扩展私有的永久组标识。

无法唯一匹配时，快照提供待恢复记录和当前候选组；主搜索增加恢复入口，展示组内页面，底栏和 Cmd+K 共用明确确认动作。执行时重新检查当前组的窗口、成员、网址、名称、颜色指纹，拒绝过期确认。确认后保留候选组当前名称与颜色，并将它们作为受管理组的预期状态；活动页带回普通标签栏，不确定的组始终不自动修改。旧版本遗留同名灰色组只用于发现候选，必须用户确认。

待恢复记录阻止在未受管窗口创建新收起组，也阻止在有候选组的窗口追加收起。用户可放弃恢复记录，页面与原生组不变。关闭自动功能会将所有仍确认受管理的成员移出组，包括手动收起的页面；待恢复且尚未确认归属的候选组不受影响。恢复记录在已管理组解除、明确人工改组或主动放弃时移除；关闭窗口的记录保留供稍后恢复。所有记录仅保存在本机，排除无痕，不保存页面正文或表单值。

## 当前决定补充（2026-10-18）

恢复核对中，点击成员卡片及卡片／列表上的普通 Enter 都只选择候选；不得自动接管或将焦点转到确认按钮。纯键盘通过 Tab 聚焦底栏「继续管理这组」，再用 Enter／Space 确认，也可通过操作菜单显式确认。此分离保证核对候选与授予管理权是两个可识别的步骤。

显式接管保留候选组的当前名称与颜色，并保存为当前受管理组的预期状态；后续收起不覆盖自定义名称与颜色，未改动的自动生成名称仍随界面语言更新，不附加成员数量。此决定替代旧版「确认后恢复为灰色」的行为，自动恢复仍遵循保守的一对一匹配条件，过期指纹仍拒绝。

关闭自动收起仍移出所有已确认受管理的成员，包括手动收起的页面；设置说明必须公开此范围。它不是仅暂停自动检查，也不改动待恢复候选组。本节记录决定，不代表已完成验收。

## 可配置闲置时长与状态（2026-10-20）

默认关闭与 7 天阈值不变。偏好新增 `autoTuckAfterHours`，接受 1 至 8760 的整数小时，缺失或非法旧数据回退 168。设置提供 1／12 小时、1／3／7 天五档预设；存储中的合法非预设时长继续显示并生效，直到用户选择预设保存。选择时长后立即保存，与语言、主题设置一致；不再要求额外点击底栏保存。修改时长保留已有计时，重新开启仍从当下计时。候选数量按已保存阈值显示，读取状态失败不阻止保存，保存本身不触发收起。

后台用 Chrome alarms 每 5 分钟检查，首次开启 1 分钟后检查；旧 30 分钟 alarm 在初始化时迁移。进入空闲／锁屏事件也触发检查。电脑空闲（60 秒无操作或锁屏）或 Chrome 连续失去焦点 30 分钟时才允许收起，每页执行前重新核对。失焦不额外触发扫描，只使用周期检查；返回 Chrome 重置等待并停止后续收起。此规则让用户长时间在其他应用工作时仍能整理，同时过滤短暂切换应用；失焦计时仅保留在浏览器会话内，后台休眠不重置，浏览器重启重新计时。打开设置或手动刷新只读取状态与候选，不重置计时、不触发收起。状态区分未到期、受保护、可收起但等待触发条件、被待恢复记录阻塞的数量，以及上次完成自动检查的时间。失败尝试在本次浏览器会话内单独记录和呈现，保留此前成功检查时间；后续成功检查清除失败状态。自动检查时间仅保存在本机，状态读取不冒充自动检查。

## 跨批次顺序（2026-10-22）

同一窗口第一次收起前的标签栏左右顺序作为后续收起的排序基准，跨批次的新成员插入对应位置，而非始终追加到组尾。只移动新收起的成员，不重排其他普通标签，也不把撤销扩展为恢复整个窗口的历史位置。新出现的标签按当前可见邻居确定位置；用户重排组内成员时尊重其选择，并以当前标签栏建立新基准。

顺序记录属于浏览器会话，跨后台休眠保留。完整浏览器重启或旧版本缺少顺序记录时以当前恢复的标签栏为新基准，不通过网址推断历史顺序，避免重复网址和新 ID 造成误排序。

## 取舍与影响

原生折叠组减少标签栏占用，同时保留搜索与页面状态；它不会主动释放页面内存，也不改变 Chrome 自身的内存节省行为。

浏览器可能部分恢复组信息或恢复多个相同的组。完整唯一匹配自动恢复，其他情况需要用户确认；不会再因为清空会话状态而彻底失去恢复途径。最近可撤销批次仍属于会话数据，不跨浏览器重启或扩展重载恢复。

新增 `tabGroups`、`alarms`、`idle` 权限分别用于原生分组、周期检查和判断电脑是否空闲；不增加网站访问权限。首次开启从当下计时，避免把未知的旧标签立即收起。

## 未采用的方案

- 自动关闭后保存 URL：无法完整恢复表单、滚动位置及页面内存状态，与“收起”的含义不符。
- 主动 discard：不会清空标签栏，重新访问需要加载，也不能替代原生折叠组。
- 仅按名称或旧组 ID 认领重启后的组：会误认用户分组，缺少足够可靠的归属依据。
- 重排整个窗口以恢复历史位置：会覆盖用户在收起之后的操作；本轮只撤销仍有效的收起结果。
