# 0010 · 网页视口与来源窗口分别锚定

状态：已采纳。记录日期：2026-10-17；更新日期：2026-10-22。本决策更新 [ADR 0001](0001-local-extension-and-overlay.md) 的独立窗口几何策略；双承载范围遵循 [ADR 0019](0019-two-palette-hosts.md)。采纳决策不代表完成实现验收。

## 背景

普通网页适合在页面视口内显示居中偏上的浮层；受限页面与地址栏场景使用独立窗口。Chrome 提供来源浏览器外框位置和标签页内容尺寸，却不直接提供内容区屏幕原点。左侧标签栏、停靠 DevTools 等布局会使内容区偏离浏览器外框中心，因此不以估算内容原点追求两种承载的屏幕坐标重合。

## 决策

Command Palette 与 Tab Switcher 共用以下规则：网页浮层锚定页面视口，独立窗口锚定来源浏览器外框；面板内容尺寸继续受来源标签页视口约束。两种承载均水平居中、偏上显示，不承诺相同屏幕坐标，也不采用显示器屏幕固定居中。

### 网页浮层与内容尺寸

网页浮层保留现有 CSS 视口布局。共享尺寸规则以 CSS 像素计算：

- 宽度为 `min(750, viewport.width - 48)`；视口宽度 ≤520 时改为减 20。
- 顶部留白为 `clamp(28, viewport.height × 0.16, 150)`；窄屏固定为 24。
- 高度为 `min(516, viewport.height - inset - 24)`；极小视口的宽高下限保护为 1px。
- `750 × 516` 是内容尺寸上限，系统标题栏与边框另计。

独立窗口的内容宽高继续使用来源标签页视口与上述尺寸规则，不改为按来源窗口外框决定尺寸。

### 独立窗口的位置与缩放

`src/panelGeometry.ts` 的共享几何供命令面板和切换器使用。Chrome 窗口与标签页 API 尺寸使用屏幕逻辑像素（DIP）；来源 `chrome.tabs.getZoom` 的缩放比例用于 DIP 与 CSS 像素换算，不以设备像素比代替页面缩放。

- **内容尺寸**：将来源 `tab.width/height` 限制在来源窗口外框以内，除以 zoom 得到 CSS 视口，按共享尺寸规则计算，再乘回 zoom。缺失尺寸使用既有回退值，不将回退值当作测量结果。
- **水平位置**：面板内容矩形相对来源窗口 `owner.left/width` 水平居中，不估算来源内容区的横向原点。
- **垂直位置**：从来源窗口 `owner.top` 向下留白。先将来源窗口外框宽高除以 zoom；CSS 宽度 ≤520 时留白为 24px，否则为 `clamp(28px, 16% × owner CSS height, 150px)`，再将留白乘回 zoom。
- **外框换算**：从内容位置扣除 popup 自身框架的左／上偏移，将框架总宽高加到内容尺寸上，最终转换为整数窗口坐标与尺寸。

位置留白使用来源窗口外框，内容高度约束中的留白仍使用来源标签页视口；两者承担不同职责。

### 原生框架校准

创建时暂以 44 DIP 顶部框架估算。独立窗口随后用 Chrome API 返回的自身外框与自身标签页内容尺寸之差测量框架，避免混用 DIP 与 DOM CSS 尺寸；框架左偏移取总宽差的一半，上偏移取总高差减去半宽差。popup 缩放跟随来源标签页，以 automatic / per-tab 模式避免影响其他扩展页。

校准在 UI 渲染前完成，切换器也在就绪交接前完成；失败时保留创建时估算。框架测量只用于 popup 自身，不用于推算来源页面的屏幕原点。系统标题栏和浏览器对窗口边界的约束仍保留。

## 取舍与边界

- 分别采用各承载可直接获取的锚点，使定位规则可预测；侧栏改变页面视口时，网页浮层可以随之移动，独立窗口仍相对来源外框居中。内容尺寸仍可能随来源视口变化。
- 共享内容尺寸与原生窗口定位规则，避免命令面板和切换器分叉。CSS 浮层与共享尺寸计算仍须保持一致。
- 原生框架校准可能产生一次窗口调整，渲染前完成不代表系统框架完全不可见；沿用来源归属、焦点、确认与取消规则。

## 未采用的方案

- **估算来源内容原点以对齐两种承载**：左右对称、底边对齐的假设无法可靠适配左侧标签栏等不对称布局。
- **显示器屏幕固定定位**：与采用网页视口和来源浏览器窗口作为锚点的需求不符。
- **固定侧栏补偿或历史指针校准**：依赖特定布局或用户先移动鼠标，无法覆盖可折叠侧栏与纯键盘流程。
- **固定原生外框尺寸或标题栏高度**：不能适配页面缩放与系统框架差异；创建阶段的估算须与最终框架测量分开。
