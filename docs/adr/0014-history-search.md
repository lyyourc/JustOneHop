# ADR 0014 · 最近一周历史混搜与显式全部时间搜索

- 状态：已采纳
- 日期：2026-10-17
- 更新：0003 的搜索来源、0007 的历史请求等待边界；0011 的原生页面命令仍仅负责跳转

## 背景

用户希望找回从任意入口访问、已经关闭且没有收藏的页面。Chrome 历史接口支持按关键词和时间范围查询；异步响应不能让候选不断插入，或把 Enter 的目标替换成另一项。用户明确选择安装时申请权限，并要求默认搜索最近一周、等待预算 100ms。

## 决策

使用必需 `history` 权限与 `chrome.history.search`，主搜索范围为最近七天，最多返回 100 个匹配页面。100 是返回上限，不是只搜索最近 100 个页面。历史不加入浏览器状态快照，也不维护跨次打开的缓存或持久索引。

UI 对整个请求（含消息传递）设置 100ms 等待预算。每轮查询仅提交一次合并结果，超时后保留其他来源结果并忽略迟到响应；查询切换也使旧响应失效。等待时保留上一轮列表但禁止执行，输入和返回可用。无匹配、超时和读取失败分别说明。

明确搜索历史功能（如 `history / 历史 / 搜索历史`）时将入口置顶并进入空的历史搜索框，返回保留主搜索命令词；普通关键词继续携带原词。在普通关键词下固定在第 5 条插入「搜索全部历史」，不足四个普通结果则置于末尾；无普通结果时成为唯一候选。这个导航入口不参与排名，包含入口后的总展示上限仍为 100 条。它承接用户主动接受等待的意图，在二级列表保留关键词并用 `startTime: 0` 搜索全部时间；超过 150ms 展示加载状态，15 秒未完成提供重试。仍设置 100 个返回上限并明确提示截断，不承诺无限分页。

历史条目进入已有相关性等级，同级下优先匹配的标签页、书签，历史之间优先最近访问。仅删除与匹配标签页／书签同 URL 的历史候选，不改变原有标签页与书签之间的重复关系。URL 比较保留路径、查询和片段。历史不写入使用习惯；打开在来源窗口新建标签页，仅接受 HTTP(S)。无痕来源不读取普通历史。

## 备选与代价

- 不采用最近 N 页预加载：会漏掉范围外的匹配，还需维护缓存更新和失效。
- 不采用逐批插入结果：破坏鼠标和快速 Enter 的目标稳定性。
- 不把全量入口放到第 100 条之后：不易发现；也不新增常驻提示条挤占面板高度。
- Chrome 的候选召回语义不等同于 zing 的本地模糊匹配；后续排序无法恢复未被 Chrome 返回的页面。
- Chrome API 无取消参数，超时是 UI 停止等待而非终止浏览器查询。历史查询故障不阻断标签页、书签与命令。
- 必需权限的 Chrome 提示涵盖读写能力，产品实现仅使用读取能力；已有用户升级新增权限可能需重新确认。
