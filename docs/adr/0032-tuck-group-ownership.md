# 0032 · 收起组按名称与窗口维持归属

状态：已采纳。记录日期：2026-10-28。依据：用户明确要求只要组名与所在窗口不变，就继续管理收起组。

## 背景

ADR 0008 将外部改颜色或加入新成员视为接管，扩展随即放弃管理但保留原生组。后续收起会创建另一组，即使原组仍叫「Tuck Away」。这一规则使普通整理操作意外中断收起功能，并产生难以区分的同名组。

## 决策

对当前浏览器会话中已确认归属的原生组，只以名称及所在窗口是否保持一致判断继续管理。颜色与成员变化属于正常编辑：沿用用户选择的颜色，当前组内成员都属于受管理范围。即使原成员被全部替换，只要该原生组仍存在且名称、窗口不变，归属也不改变。

在 Chrome 原生界面改名或跨窗口移动后仍停止管理。通过 JustOneHop 的组管理操作改名会同步预期名称，继续保留归属。

撤销仍只处理扩展最近收起的批次，不纳入手动加入的成员。选择组内任一页面仍将它带回普通标签栏；关闭自动收起时移出全部受管理成员，包括手动加入的页面。并发成员变化可以暂停当前批次以重新核对，但不能因此放弃管理、创建替代组。

完整浏览器重启后，旧窗口和组的数字 ID 不足以确认身份，沿用恢复记录与一对一核对；颜色和成员记录随正常编辑更新。其他同名组不因此自动被认领，已存在的重复组也不自动合并。

## 取舍

放宽颜色和成员条件让用户可以自然编辑收起组，代价是手动加入的标签也参与找回与关闭功能时的移出操作。明确保留撤销批次边界，避免撤销一次自动整理时连带移出手动加入的页面。

仅凭同名自动合并或认领所有组，会改变未确认归属的分组，因此不采用。此决策不改变持久数据结构或对外接口。
