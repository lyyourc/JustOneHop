# 0019 · 命令面板收敛为页面浮层与独立窗口

状态：已采纳。日期：2026-10-18。更新 [0001](0001-local-extension-and-overlay.md) 与 [0010](0010-content-anchor-panel-geometry.md) 的工具栏弹窗兜底决策，不改变几何算法或暂停中的屏幕定位目标。

## 背景

页面浮层、贴工具栏的 action popup、独立窗口形成三种不同的展示位置。工具栏弹窗没有自由定位接口，先打开弹窗不能解除受限页面的注入限制，也不能保证网页获得地址栏的键盘焦点。用户选择保留普通网页浮层，将第三种承载移除。

## 决策

扩展图标与启动快捷键共用 `paletteLaunch`。Chrome 内置页直接打开来源绑定的独立窗口；普通网页尝试注入，只有明确收到浮层就绪回复才结束启动。普通网页无法获取键盘焦点时仍创建浮层，保留自动聚焦尝试，并提示用户点击搜索框；只有无法注入或创建浮层时，重新核对来源标签仍活动、所属窗口与 URL 未变，然后使用同一独立窗口兜底，不先打开工具栏弹窗。

后台启动清除默认及现存标签页的旧 action popup 配置，启动和导航继续清除单页配置；不再写入非空配置或调用 `action.openPopup`。这避免旧版本的每标签页覆盖让图标点击绕过统一启动判断。

独立窗口继续保存原始来源与令牌，执行操作针对来源，复用既有焦点检查、主层 Esc、重复启动、失焦和来源删除关闭规则。并发启动有单页保护。普通页注入失败后不会追随已切换或导航的来源创建新窗口。

## 取舍

- 保留普通页面的轻量浮层，失焦时接受需要一次真实点击的代价；只有无法承载浮层的页面接受独立窗口的系统标题栏和焦点交接。
- 脚本 `click()`／合成鼠标事件不等价于真实用户输入；`window.focus()` 和输入框 `focus()` 只能尽力恢复，不保证从地址栏夺回焦点。不新增 debugger 权限或原生鼠标自动化。Tab Switcher 的焦点校验与松键确认策略不在此决策范围内。
- 不新增权限，不引入工具栏弹窗到其他承载的状态迁移，也不将全部页面改为独立窗口。
- 独立窗口仍按来源内容区与缩放估算几何，垂直标签栏的对齐限制仍存在；本次不宣称屏幕坐标定位目标已经实现。
- `popup.html` 继续作为独立窗口及持久配置说明标签页的页面资源；文件名和 App 的非浮层模式不代表仍提供工具栏 action popup。
