# ADR 0029：页面顶部按任务区分搜索与导航

- 状态：已采纳；设置内子页的顶部与返回位置由 ADR 0030 局部覆盖，独立任务／详情页保留本决策
- 日期：2026-10-22
- 关系：部分替代 ADR 0009 对非列表页面返回位置的规定；补充 ADR 0028 的图标编辑布局；设置框架范围由 [ADR 0030](0030-settings-navigation-shell.md) 调整

## 背景

搜索列表需要稳定的输入位置，但无检索需求的编辑页若将普通标题放进搜索胶囊，会暗示一个实际上不存在的输入行为。统一组件应保持任务语义与操作可预测性，无需要求所有页面拥有相同形态的 Header。

用户提供的 Raycast「Import Snippets」截图展示了另一种分工：左上角返回、正文呈现任务标题与说明、底栏承载页面身份和主要动作。本决策借鉴这种分工，保留本项目的 Chrome 配色、紧凑尺寸与共享底栏，不要求复制截图中的背景、装饰或比例。

## 决策与取舍

- 有检索需求的页面保留搜索栏及底栏导航，列表之间的搜索位置继续稳定。
- 无检索需求的表单、单步任务和详情页面采用轻量顶部导航。返回位于左上角，标题、说明和预览属于正文；底栏省略重复返回，继续提供页面身份、主次动作与结果反馈。
- 原决策将搜索图标编辑归为独立任务页；[ADR 0030](0030-settings-navigation-shell.md) 将其纳入持续可见的设置框架，保留跨分类搜索与底栏返回。输入 Emoji 仍是有标签的表单字段，不承担页面搜索；图片预览不使用搜索输入框外观。
- 导航位置因页面类型不同而变化，代价是两种顶部形态；通过固定的页面类型规则、相同 Esc／返回层级、完整上下文恢复和可见鼠标入口维持可预测性。
- 内容布局服从任务复杂度：单步任务可居中，多字段编辑与长内容优先可读和滚动，不为视觉装饰增加面板尺寸。

## 边界

本决策不改变搜索、保存、关闭或草稿的业务语义，也不引入全局主题改版。配置指南、收起恢复核对与存储详情等独立任务／详情页继续使用顶部返回；设置框架及其内部子页按 ADR 0030 使用持续搜索、分类导航和底栏返回，覆盖范围取决于页面是否属于设置框架，不扩展至独立任务页。搜索列表和确认弹层保留各自语义。实现和实际验证分别确认，不沿用此前截图或自动化作为新布局通过证据，当前范围见 [验收记录](../ACCEPTANCE.md)。

当前行为契约见 [交互架构 §5.1](../INTERACTION-ARCHITECTURE.md#51-页面顶部与搜索栏-searchbar)，历史取舍见 [ADR 0009](0009-list-page-footer-breadcrumb.md)。
