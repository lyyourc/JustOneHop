> [!IMPORTANT]
> **文档维护原则**：本文档是当前系统发布状态与验收能力的**全局全貌基线**，**严禁追加单次任务的过程性测试流水账**（如临时 runner 耗时、重试次数、本地 `test-results/runs/...` 路径等）。日常测试结果体现于命令输出或 Git Commit 描述；仅当新增验收维度、系统级能力状态变更或发现新的受限边界时，对本文档进行**就地更新**。

## 2. 验证环境分层与证据效力

在评估验证结论时，严格区分环境层级，不得以低层证据直接推断高层结论：

```
+-------------------------------------------------------------+
| 层级 3: 日常 Chrome 真实生产环境 (Daily Chrome Runtime)        |
| - 真实用户资料、实体按键触发、浏览器真实地址栏焦点与窗口层叠      |
+-------------------------------------------------------------+
                              ▲
+-------------------------------------------------------------+
| 层级 2: 隔离浏览器自动化 (Isolated Chrome for Testing)        |
| - 临时 Profile、闭合 Shadow DOM、CDP 真实键盘事件、真实渲染尺寸 |
+-------------------------------------------------------------+
                              ▲
+-------------------------------------------------------------+
| 层级 1: 内存与静态逻辑 (Node.js Unit Tests / Direct UI)       |
| - tsx / Node test runner、类型检查、状态机与算法断言           |
+-------------------------------------------------------------+
```

1. **层级 1（逻辑与状态）**：验证纯逻辑、排序权重、存储淘汰、状态机转移与国际化文案。通过仅证明算法逻辑正确。
2. **层级 2（隔离自动化）**：验证组件在标准 Chromium 环境中的真实渲染、几何外框、事件拦截与交互流转。其中独立 UI 测试加载真实构建产物、模拟 Chrome API，仅证明组件对给定响应的行为；扩展集成测试使用真实扩展与独立 Profile，承担后台消息、存储、权限和原生标签／窗口的验证。两者不可互相替代；自动化测试通过仅证明所用环境下的既定用例。
3. **层级 3（日常实机）**：验证与日常 Chrome 扩展生态（如 Vimium）、原生全屏、多显示器缩放、系统深浅色切换及用户手工操作的实际融合体验。

## 3. 已知受限与待解决项 (Known Limitations & Deferred Boundaries)

以下为当前版本明确已知的受限边界或架构演进中暂停的工作，不作为质量缺陷宣称已解决：

1. **双承载定位偏差与暂停的屏幕定位目标（[ADR 0010](adr/0010-content-anchor-panel-geometry.md)）**：
   - 网页浮层基于实际内容视口布局；独立窗口以浏览器外框和标签页内容尺寸估算内容原点，无法准确定位不对称侧栏。
   - 在 Chrome 156、左侧标签栏占 240 DIP 的验证条件下，100%、125%、80% 缩放均出现约 120 DIP 水平偏差。该限制尚未解决，不能宣称两种承载已精确对齐；多显示器与其他侧栏尺寸不在此证据范围内。
   - 待实现目标是按所在显示器的屏幕坐标水平居中、从屏幕顶部计算垂直位置，具体垂直偏移未定；不是垂直居中。该工作仍暂停。
2. **浏览器自动化稳定性**：
   - 隔离 Chrome 的上下文关闭曾超过 30 秒，导致用例主体完成后仍以收尾超时失败。当前工作树的双 worker 全量验证未出现收尾超时或新增失败，但历史超时根因未确定，单轮完整执行不能证明长期稳定性。
   - 当前后台生命周期压力用例在全量并发环境完成 100 次目标 worker 停止、100 次成功请求与运行状态恢复、20 次扩展重载，未出现脚本加载错误。历史全局停止 service worker 调用不返回及停止后页面／上下文／浏览器关闭的问题尚未根因定位；目标 worker 场景通过不能证明全局停止故障已修复，不得以提高超时或减少压力次数替代验证。
3. **外部删除来源标签页直接结束会话**：
   - 若用户在小范围瞬移面板处于打开状态时，通过外部快捷键或鼠标关闭了唤起该面板的来源标签页，面板会话将立即安全退出，不进行跨标签页迁移接续。
4. **自动化测试无法完全替代 CDP 实体修饰键松开**：
   - 标准 WebDriver / Playwright 缺乏原生的系统级修饰键独立松开事件，自动化测试采用 CDP 底层协议注入按键序列作为替代证据，最终松键交互需以日常实机表现为准。

## 4. 验证指令索引

日常开发与重构时，按需执行对应分层的最小充分验证：

```sh
# 1. 静态检查与全量逻辑单测（层级 1）
npm run typecheck
npm test

# 2. 定向单测执行
npx --no-install tsx --test tests/tabTuck.test.ts
npx --no-install tsx --test tests/usage.test.ts

# 3. 生产产物构建校验
npm run build

# 4. 隔离浏览器端到端交互回归（层级 2）
npm run test:e2e -- --grep 'storage and Tab Group layers preserve main palette geometry'
npm run test:e2e -- tests/tabTuck.spec.ts

# 5. 存储与切换器独立手动验证夹具
node tests/storage-manual.mjs
node tests/switcher-manual.mjs
```
