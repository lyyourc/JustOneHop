# 评审标准

本文件用于评审实现方案、跨视图改动与验证结论。具体交互契约见 [交互架构](INTERACTION-ARCHITECTURE.md)，验证入口与隔离方式见 [测试指南](TESTING.md)。类型、构建和可重复执行的行为由工具检查；这里保留需要判断的问题。

## 跨视图一致性

从用户的同一意图比较主搜索、二级页面、Command Palette 与 Tab Switcher 的对应路径：目标、可用性、反馈和返回后的上下文是否一致？鼠标、键盘和交替流程是否仍可独立完成？共享组件的调整需考虑所有调用方及网页浮层、独立窗口的焦点边界，不能只凭改动页看起来正确推断其他页面正确。

优先让已有组件承载相同语义；不同语义可以保留明确差异，例如切换器悬停不改变松键目标。评审判断差异是否来自用户操作语义，而非某个页面漏接共享逻辑。视觉相似不等于行为相同，代码复用也不自动证明一致性。

## 需求与当前实现

以用户最后明确的目标解释改动，并区分目标、当前行为和未解决约束。实现限制可以形成待解决问题，不能悄悄重写需求；历史验收也不能替代当前目标。定位场景的具体边界见 [ADR 0010](adr/0010-content-anchor-panel-geometry.md#待实现目标)。

新增权限、持久状态或承载方式是否确实服务于该目标？它们对本地隐私、纯键盘路径、原生对象归属及失败后的恢复有什么影响？组件契约或架构取舍发生变化时，把决策写回对应权威文档，让后续视图沿用同一依据。

## 独立证据与结论范围

测试的预期值应来自需求或独立观测。用与实现相同的估算公式计算预期坐标，只能证明两处公式一致；不能证明与真实屏幕位置一致。判断时问：即使产品仍有被报告的问题，这个测试是否仍可能通过？

检查夹具改变了什么，以及因此能证明什么。打开 Shadow DOM 便于结构断言，但不能替代生产闭合 Shadow DOM / iframe 的键盘验证；模拟焦点或命令回调可以锁定处理分支，但不等同于原生地址栏或实体快捷键全链路。需要这类结论时，补相应环境的独立观测；暂缺证据时保留边界。

验收结论应对应实际构建、所选用例与浏览器环境。区分通过、跳过、失败、重跑和未验证；记录失败后的修改及最终覆盖范围。构建成功、部分用例通过、截图符合预期各自只支持相应结论，不扩展为定位已解决、完整套件通过或日常 Chrome 已重载。
